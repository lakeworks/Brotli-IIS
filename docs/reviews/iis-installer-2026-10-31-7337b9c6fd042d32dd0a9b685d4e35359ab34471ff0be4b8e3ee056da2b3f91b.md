# Review: IIS installer + PDBALTPATH (8f986e24)

Static review of `install-iis.ps1`, `build-x64.ps1` (`/PDBALTPATH`), `readme.md` install section, and `CLAUDE.md` Levels paragraph against the plan and `CLAUDE.md` Deployment rules.

## Summary

No Critical findings. The installer stays inside the `br` scheme and optional `<httpCompression>` proxy attributes, refuses to overwrite a differently hashed on-disk DLL, pins the binary by SHA-256, and gates WWW restart on `-RestartWww`. `/PDBALTPATH:%_PDB%` is correctly wired to the DLL linker flags only. Several Operational gaps remain around recovery messaging, same-session re-run, and `ShouldProcess` composition.

### [O1] Install success path never prints a rollback command; backup name is printed only after all mutations

Plan end-state: print scheme list, backup name, **rollback command**, and restart guidance.

Evidence: after a successful change block the script prints only `Backup: $backup` (`install-iis.ps1:268`) and optional `Write-RestartNote` (`:149-155`, `:285`). It never prints `.\install-iis.ps1 -Rollback` or `appcmd restore backup "…"`. The rollback path does print the restore command (`:197`).

Worse for partial failure: `$backup` is chosen at `:247`, then copy / `Set-BrScheme` / proxy / state run at `:251-267`, and only then is the name printed (`:268`). If `Set-BrScheme` throws after `/-` remove and before `/+` add (`:123-127`), `br` is gone, the appcmd backup exists, and the thrown error does not name it. Operator recovery falls to listing backups by hand.

### [O2] `Add-Type` AVX2 probe breaks same-session idempotent re-run

Help and plan: re-running with the same inputs changes nothing.

Evidence: every Install run executes unconditional `Add-Type -Namespace BrotliIis -Name Cpu …` (`install-iis.ps1:205`) with `$ErrorActionPreference = 'Stop'` (`:66`). On a second invocation in the same Windows PowerShell 5.1 or PowerShell 7 process, `Add-Type` throws that the type already exists, before the idempotence short-circuit at `:244-245`. A new process works; a typical elevated admin window re-run does not.

### [O3] Independently gated `ShouldProcess` steps allow mutations without a backup

`SupportsShouldProcess` is required so `-WhatIf` / `-Confirm` cover every change.

Evidence: backup (`:248-250`), copy (`:251-255`), scheme (`:256-258`), proxy (`:259-261`), and state (`:262-267`) each call `ShouldProcess` separately. With `-Confirm`, declining the backup prompt and accepting a later prompt applies scheme/DLL/proxy changes with no `appcmd add backup`. Under `-WhatIf` all return false, so dry-run stays safe; the Confirm composition does not.

Default runs (no `-Confirm`) still create the backup first, so the common path is intact.

### [O4] `-ProxyFriendly`-only updates give no recycle guidance

`CLAUDE.md:42` states `noCompressionForProxies` (and like attributes on `<httpCompression>`) take effect after an app-pool recycle; scheme `dll` / level changes need a WWW restart ([Microsoft scheme reference](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/httpcompression/scheme/)).

Evidence: `$changed = $copyNeeded -or $schemeNeeded` (`install-iis.ps1:280`) omits `$proxyNeeded`. A run that only flips the two proxy attributes writes config (`:259-261`) and prints neither `Write-RestartNote` nor a pool-recycle hint. The readme’s primary example passes `-RestartWww` as well, which masks this; `-ProxyFriendly` alone does not.

### [P1] `CLAUDE.md` still claims only `build-x64.ps1` and `CLAUDE.md` are local additions

Evidence: `CLAUDE.md:93` — “only the `build-x64.ps1` script and this CLAUDE.md are local additions”. `install-iis.ps1` is a new root script in this change set; the Files list (`:81-89`) also omits it. Factual drift relative to the public fork tree.

### [P2] Help text overstates that every change goes through `appcmd.exe`

Evidence: `.DESCRIPTION` (`install-iis.ps1:8-9`) says “Every change goes through appcmd.exe”. Directory create, `Copy-Item` of the DLL, state-file write/remove, and `Restart-Service` do not. `-WhatIf` coverage for those paths is via `ShouldProcess`, which is fine; the sentence is not.
