### [O1] Unguarded `Add-Type` throws on re-run in Windows PowerShell 5.1

- **File**: [install-iis.ps1:205-208](../../install-iis.ps1#L205-L208)
- **Impact**: In Windows PowerShell 5.1 (standard on Windows Server installations), calling `Add-Type -Namespace BrotliIis -Name Cpu -MemberDefinition ...` when the `BrotliIis.Cpu` type has already been compiled in the current AppDomain/session generates a terminating error under `$ErrorActionPreference = 'Stop'`:
  `Add-Type : Cannot add type. The type name 'BrotliIis.Cpu' already exists.`
- **Evidence**:
  ```powershell
  205: Add-Type -Namespace BrotliIis -Name Cpu -MemberDefinition '[DllImport("kernel32.dll")] public static extern bool IsProcessorFeaturePresent(uint feature);'
  206: if (-not [BrotliIis.Cpu]::IsProcessorFeaturePresent(40)) {
  ```
  This breaks:
  1. The documented usage sequence in [readme.md:13-14](../../readme.md#L13-L14) and [install-iis.ps1:32-34](../../install-iis.ps1#L32-L34), where an administrator runs `-WhatIf` first and immediately executes the install command in the same console.
  2. Idempotence verification where an operator re-runs the script in the same console.
- **Remediation**: Guard type creation with a type-existence check:
  ```powershell
  if (-not ('BrotliIis.Cpu' -as [type])) {
      Add-Type -Namespace BrotliIis -Name Cpu -MemberDefinition '[DllImport("kernel32.dll")] public static extern bool IsProcessorFeaturePresent(uint feature);'
  }
  ```

### [O2] `-VerifyUrl` executes live network requests and throws during `-WhatIf` runs

- **File**: [install-iis.ps1:281-289](../../install-iis.ps1#L281-L289)
- **Impact**: When `install-iis.ps1` is executed with `-WhatIf` and `-VerifyUrl` (e.g. alongside `-RestartWww`), `Restart-Www` honors `ShouldProcess` and skips restarting the service, but line 283 invokes `Test-BrResponse` without checking `$WhatIfPreference`:
  ```powershell
  281: if ($RestartWww) {
  282:     Restart-Www
  283:     if ($VerifyUrl) { Test-BrResponse $VerifyUrl }
  ```
  `Test-BrResponse` ([install-iis.ps1:136-147](../../install-iis.ps1#L136-L147)) executes `curl.exe` against the live endpoint. Because the installation and service restart were simulated and not applied, the target does not return `Content-Encoding: br`, causing line 145 to throw:
  `throw "Verification failed: $Url answered Content-Encoding '$enc' to a br-only request..."`
  Similarly, if `-RestartWww` is not supplied and `$changed` evaluates to false, line 288 executes `Test-BrResponse` under `-WhatIf`. A `-WhatIf` simulation should never generate live network probes or terminate with a verification error.
- **Remediation**: Gate verification calls with `-not $WhatIfPreference`, e.g.:
  ```powershell
  if ($VerifyUrl -and -not $WhatIfPreference) { Test-BrResponse $VerifyUrl }
  ```

### [P1] Backup message displayed when `appcmd add backup` is skipped under `-WhatIf`

- **File**: [install-iis.ps1:248-268](../../install-iis.ps1#L248-L268)
- **Impact**: In [install-iis.ps1:248-250](../../install-iis.ps1#L248-L250), backup creation is gated by `$PSCmdlet.ShouldProcess`:
  ```powershell
  248:     if ($PSCmdlet.ShouldProcess('applicationHost.config', "Create appcmd backup $backup")) {
  249:         Invoke-AppCmd @('add', 'backup', $backup) | Out-Null
  250:     }
  ```
  Under `-WhatIf`, line 249 is skipped. However, line 268 (`Write-Host "Backup: $backup"`) executes unconditionally at the end of the block, reporting `Backup: brotli-iis-...` to the operator even though no backup was written to `%windir%\system32\inetsrv\backup`.
- **Remediation**: Move line 268 inside the `ShouldProcess` block or guard it with `if (-not $WhatIfPreference)`.

### [P2] Incompatible `appcmd` attribute removal syntax `/-$a` in rollback branch

- **File**: [install-iis.ps1:186-190](../../install-iis.ps1#L186-L190)
- **Impact**: In the rollback logic:
  ```powershell
  186:             if ($old -eq '') {
  187:                 Invoke-AppCmd @('set', 'config', "-section:$Section", "/-$a", '/commit:apphost') | Out-Null
  188:             } else {
  189:                 Invoke-AppCmd @('set', 'config', "-section:$Section", "/${a}:$old", '/commit:apphost') | Out-Null
  190:             }
  ```
  In `appcmd.exe`, the `/ -` switch is collection syntax (e.g., `/-[name='br']`). If passed an attribute name (e.g., `/-noCompressionForProxies`), `appcmd` treats it as a non-existent collection element and fails (`Cannot find requested collection element`). Because [install-iis.ps1:87](../../install-iis.ps1#L87) queries with `/config:*`, effective schema defaults (`true`/`false`) are currently recorded rather than empty strings, making this branch unreachable in standard flows.
- **Remediation**: If an attribute needs to be cleared or reset, set it to its default value or clear the XML attribute rather than using `/ -`.
