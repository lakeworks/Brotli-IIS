## Review

### [O1] Undo fails when the previous DLL has the same version

`install-iis.ps1:143` generates an undo command that reinstalls the previous DLL through this installer. However, `:207–223` derives the destination solely from its version and refuses an existing file with a different hash.

For example, an existing `br` points to another directory’s 1.2.1 DLL. Installing the rebuilt 1.2.1 release succeeds, but the generated undo command then targets the newly occupied `brotli-1.2.1.dll` and fails with the hash-conflict error. The previous file remains available, yet the advertised targeted recovery cannot restore it.

Generate a command that repoints the preserved DLL directly, or identify this case and direct the operator to the backup fallback.

### [O2] Recovery commands assume `appcmd` is on PATH

`install-iis.ps1:136`, `:150` and `:153` print bare `appcmd` commands for removing `br`, restoring proxy attributes and restoring the backup. The fresh-server instructions run from the download directory, and the installer neither changes PATH nor documents that prerequisite.

Microsoft explicitly states that `appcmd.exe` is absent from PATH by default. Consequently, these recovery commands fail with command-not-found in the documented environment. Print PowerShell-compatible invocations using the resolved executable path and call operator. [Microsoft AppCmd documentation](https://learn.microsoft.com/en-us/iis/get-started/getting-started-with-iis/getting-started-with-appcmdexe#how-to-use-appcmdexe)

Static tracing supports the linker flag reaching DLL linking separately from the static archiver. Microsoft confirms `%_PDB%` expands without directory information. Actual rebuilt-binary inspection remains required. [Microsoft linker reference](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path)
