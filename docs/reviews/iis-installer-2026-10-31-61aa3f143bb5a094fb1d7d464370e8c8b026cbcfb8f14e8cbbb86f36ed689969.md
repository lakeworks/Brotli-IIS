### [O1] Undo note’s soft-restore command is not runnable from the note’s location

`install-iis.ps1:248-261` writes the undo note to `%ProgramFiles%\IIS\IIS Compression\brotli-iis-undo-<stamp>.txt`. The soft-restore line at `install-iis.ps1:143` is:

```text
.\install-iis.ps1 -DllPath '<absolute-prev-dll>' -ExpectedSha256 ... -RestartWww
```

`-DllPath` is absolute; `.\install-iis.ps1` is not. Help (`:16-18`) and `readme.md:19` present that line as the exact recovery command and say the note lives next to the DLLs. From that directory the relative script path does not resolve unless `install-iis.ps1` was copied there. Immediate paste from the console while still in the download folder works; later recovery from the persisted note does not.

`appcmd restore backup` remains available for a full config revert. Soft undo, the path meant to reinstall the previous DLL through the same installer, needs an absolute script path (for example `$PSCommandPath` at note-write time) or an explicit cwd instruction in the note.

### [P1] Help says `-Confirm` asks once; `-RestartWww` prompts again

`install-iis.ps1:10` says “`-Confirm` asks once for the whole change set.” Config mutations share one `ShouldProcess` (`:257-258`), which is correct. `Restart-Www` (`:159`) is a second `ShouldProcess` for W3SVC, so `-Confirm -RestartWww` asks twice. Align the help with the restart prompt, or fold restart into the same confirmation when `-RestartWww` is set.

### [P2] readme overstates what the undo command restores

`readme.md:19` says the undo note has “the exact command that reinstalls the previous DLL and settings.” The command restores previous DLL content and levels via this script (and always registers `br` first). Proxy attributes need the separate `appcmd` line in the note (`install-iis.ps1:149-150`); a middle-position `br` is not restored to its old index without `appcmd restore backup`. The script help (`:16-19`) already separates those pieces; the readme should match.
