## Detailed Evaluation

### 1. `install-iis.ps1` Behavior & Compatibility (PowerShell 5.1 & PowerShell 7)
- **PowerShell compatibility**: Syntax structures (`[ordered]@{}`, `[xml]`, `Resolve-Path -LiteralPath`, `Get-FileHash`, `Add-Type` member definition, `[Environment]::Is64BitOperatingSystem`) are fully compatible with both Windows PowerShell 5.1 and PowerShell 7+.
- **`appcmd.exe` quoting and exit codes**: 
  - Every `appcmd` call routes through [`Invoke-AppCmd`](../../install-iis.ps1#L75-L82), which verifies `if ($LASTEXITCODE -ne 0)` and throws with the exit code and captured stderr/stdout, mitigating PowerShell's default behavior where native process errors do not trigger terminating exceptions under `$ErrorActionPreference = 'Stop'`.
  - In [`Set-BrSchemeFirst`](../../install-iis.ps1#L117-L131), when updating in-place or inserting with `/+[@start,$list]`, attribute values are single-quoted. Line 119 rejects any attribute containing a single quote.
- **Rollback and undo note**:
  - Prior to modifying configuration, an `appcmd add backup` is created ([line 271](../../install-iis.ps1#L271)), and [`Get-UndoText`](../../install-iis.ps1#L137-L168) generates a self-contained undo script written to `$TargetDir\brotli-iis-undo-<timestamp>.txt`.
  - The undo commands restore prior attributes attribute-by-attribute using the absolute path to `appcmd.exe`, point back to the preserved previous DLL, restore proxy settings, and provide the command for `appcmd restore backup`.
- **Partial-failure states**:
  - If binary copying fails, configuration remains unchanged.
  - If scheme re-registration at `@start` fails after removing an existing non-first scheme, running workers retain the loaded DLL in memory, and the pre-written undo note provides the `appcmd restore backup` command ([line 151](../../install-iis.ps1#L151)).
- **`-VerifyUrl` validation**:
  - Enforces `-RestartWww` during preflight ([line 193](../../install-iis.ps1#L193)), preventing false certification against an un-restarted worker running a stale binary.
  - Headers are retrieved using `curl.exe -sS -o NUL -D - --max-time 30 -H 'Accept-Encoding: br' $Url` ([line 182](../../install-iis.ps1#L182)). Regex pattern matching `(\S+)` ignores trailing `\r\n` line endings, and exit codes are verified.

### 2. Isolation & Server Configuration Safety
- **Scheme order & preservation**: Schemes are enumerated via [`Get-CompressionConfig`](../../install-iis.ps1#L84-L99). Only the `br` entry is added or repositioned via `/+[@start,...]`. Other compression schemes (`gzip`, `deflate`) and MIME configurations (`<staticTypes>`, `<dynamicTypes>`) remain untouched.
- **DLL in use**: The target destination is versioned (`brotli-<version>.dll`). If a file with the target version already exists with a conflicting hash, the installer throws and halts without attempting an overwrite ([lines 233-239](../../install-iis.ps1#L233-L239)).

### 3. Build & Triplet Linker Flags
- In [`build-x64.ps1`](../../build-x64.ps1#L101-L128), `$dllLinkerFlags = (@($ltoLinkerFlag, '/PDBALTPATH:%_PDB%') | Where-Object { $_ }) -join ' '` injects `/PDBALTPATH:%_PDB%` into `VCPKG_LINKER_FLAGS_RELEASE`.
- `VCPKG_STATIC_LINKER_FLAGS_RELEASE` receives only `$ltoLinkerFlag`, ensuring `lib.exe` is not passed `/PDBALTPATH`.
- MSVC linker expands `%_PDB%` to the filename `brotli.pdb`, eliminating absolute build host paths from the PE debug directory (`IMAGE_DEBUG_TYPE_CODEVIEW`).

### 4. Documentation Accuracy
- [`readme.md`](../../readme.md#L9-L19) accurately documents the download and verification steps, explicitly invoking `curl.exe` (avoiding PowerShell 5.1's `curl` alias to `Invoke-WebRequest`).

## Findings

### [P1] Preflight validates 64-bit OS but does not guard against 32-bit PowerShell process
In [`install-iis.ps1:195`](../../install-iis.ps1#L195), preflight checks `[Environment]::Is64BitOperatingSystem`. If an administrator runs the script from a 32-bit PowerShell session (`%windir%\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`) on a 64-bit host, `[Environment]::Is64BitOperatingSystem` is true, but `[Environment]::Is64BitProcess` is false. Under WoW64, `$env:ProgramFiles` in line 70 resolves to `C:\Program Files (x86)` rather than `C:\Program Files`. Consequently, the 64-bit DLL and undo script would be placed under `C:\Program Files (x86)\IIS\IIS Compression` instead of the canonical `C:\Program Files\IIS\IIS Compression`.

*Recommendation*: Add `if (-not [Environment]::Is64BitProcess) { throw 'This script must be run from a 64-bit PowerShell host.' }` or resolve `$env:ProgramW6432` if defined.

### [P2] Unchecked null on `$Br.Attrs['dll']` in `Get-UndoText`
In [`install-iis.ps1:155`](../../install-iis.ps1#L155), `$prevDll = [Environment]::ExpandEnvironmentVariables($Br.Attrs['dll'])` attempts environment expansion on the existing `dll` attribute. If an existing `br` entry in `applicationHost.config` was malformed and lacked a `dll` attribute, `$Br.Attrs['dll']` evaluates to `$null`. In both .NET Framework and .NET Core, `[Environment]::ExpandEnvironmentVariables($null)` throws an uncaught `ArgumentNullException` during undo text construction before changes are applied.

*Recommendation*: Guard the lookup with `if ($Br.Attrs.Contains('dll') -and $Br.Attrs['dll'])` before invoking `ExpandEnvironmentVariables`.
