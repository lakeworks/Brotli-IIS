## Review

### [O1] Preserve existing compression enable/disable flags

`install-iis.ps1:124` removes an existing `br` entry, but its replacement preserves only the DLL and levels. `Get-CompressionConfig` (`:92`) also omits `doStaticCompression` and `doDynamicCompression`.

Consequently, upgrading a scheme configured with `doDynamicCompression="false"` enables dynamic Brotli after restart. Rollback cannot recover those flags either. Microsoft documents both defaults as `true`. Preserve these attributes when updating and restoring existing schemes. [Microsoft scheme reference](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/httpcompression/scheme/)

### [O2] Save recovery state before changing configuration

The rollback state is written at `install-iis.ps1:262`, after scheme replacement and proxy configuration.

If removing `br` succeeds but re-adding it fails (`:126`), the server retains no `br` registration and this attempt has no saved rollback state. Likewise, failure after repointing the scheme can leave `-Rollback` unavailable or using an older installation’s state. A successful retry can then record the already-modified configuration as its baseline.

Persist usable recovery information before the first configuration mutation, and retain it through failures.

### [O3] Declining a prerequisite must stop dependent changes

The independent confirmations at `install-iis.ps1:248`, `:251`, and `:256` allow an operator using `-Confirm` to decline the backup or DLL copy but accept scheme registration. That can register a nonexistent DLL or change configuration without the promised backup.

Rollback similarly allows declining restoration at `:176` and subsequently accepting deletion of its state at `:193`. Track completed prerequisites and retain recovery state until restoration succeeds. PowerShell explicitly exposes `-Confirm` through `SupportsShouldProcess`. [PowerShell confirmation guidance](https://learn.microsoft.com/en-us/powershell/scripting/learn/deep-dives/everything-about-shouldprocess)

### [O4] Rollback does not restore the previous scheme order

`install-iis.ps1:264` saves no original position. Rollback at `:178` calls `Set-BrScheme`, which always inserts at `@start`.

Starting with `gzip, br`, installing and rolling back produces `br, gzip`. This changes compression negotiation after the advertised undo operation: Microsoft documents registration order as the equal-quality tie-breaker on IIS 10 version 1803 and later. Save and restore the original position. [Microsoft prioritization reference](https://learn.microsoft.com/en-us/iis/extensions/iis-compression/using-iis-compression#compression-scheme-prioritization)

### [O5] Proxy-only changes omit activation guidance

At `install-iis.ps1:280`, `$changed` excludes `$proxyNeeded`. Therefore, adding `-ProxyFriendly` to an otherwise matching installation changes configuration but prints no restart/recycle guidance; with `-VerifyUrl`, it immediately checks the existing workers.

That misses the explicit recycle instruction in `CLAUDE.md:42`. Account for proxy-only changes when reporting activation requirements and deciding whether verification is meaningful.

### [O6] Requested verification can succeed without being performed

`install-iis.ps1:138` warns and returns successfully when `curl.exe` is absent. Thus an explicit `-VerifyUrl` request can finish successfully without establishing the required `Content-Encoding: br` result.

Check verifier availability before installation when verification is requested, and fail clearly if unavailable.

### [P1] Complete the target-server installation instructions

`readme.md:9` starts with local `install-iis.ps1` and DLL files already present. It supplies neither a fork-release download link nor instructions for obtaining the matching script, and omits the planned explicit curl verification example. Add those steps so the documented deployment works from a fresh target VM.

Static inspection supports the linker change: both LTO variants populate `VCPKG_LINKER_FLAGS_RELEASE`, which the pinned vcpkg toolchain forwards to the DLL linker independently of the static archiver. Microsoft confirms `%_PDB%` expands to the PDB filename without its path. Actual rebuilt-binary path removal remains a release check. [Microsoft linker reference](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path)
