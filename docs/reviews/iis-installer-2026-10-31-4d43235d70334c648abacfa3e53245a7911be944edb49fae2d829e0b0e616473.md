## Review

### [O1] Nested confirmations can bypass recovery prerequisites

`install-iis.ps1:146–147` calls `New-Item` and `Set-Content` without suppressing their confirmations. With `-Confirm`, accepting the outer change set at `:342` does not prevent these additional prompts. Declining the state-file writes can leave IIS changes applied without the recorded rollback baseline.

Likewise, declining the nested `Restart-Service` confirmation at `:155` still makes `Restart-Www` report success and return `$true`. Suppress nested confirmations after the outer approval and verify required operations succeeded. [PowerShell confirmation guidance](https://learn.microsoft.com/en-us/powershell/scripting/learn/deep-dives/everything-about-shouldprocess#suppressing-nested-confirm-prompts)

### [O2] Rollback does not restore a middle scheme position

`install-iis.ps1:240–244` deliberately restores a previously middle `br` entry last. For example, `gzip, br, deflate` becomes `gzip, deflate, br` after install and rollback. The state file is then removed at `:251`, despite the original order remaining unrestored.

This changes negotiation for clients accepting `br` and `deflate` equally. Preserve and restore the original index or neighboring scheme. [Microsoft scheme-priority documentation](https://learn.microsoft.com/en-us/iis/extensions/iis-compression/using-iis-compression#compression-scheme-prioritization)

### [O3] Repeat execution forgets pending activation

`install-iis.ps1:362–369` records completion before restarting, while `:198` checks activation only against changes made during the current invocation.

Consequently, install an upgrade without `-RestartWww`, then rerun identical inputs with `-VerifyUrl`: the second invocation detects no changes and can report successful verification against the previously loaded Brotli DLL. It also omits the pending-restart warning. Persist pending activation or require the restart before treating this verification as acceptance of the installed candidate. [Microsoft scheme restart requirements](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/httpcompression/scheme/#attributes)

Static inspection supports the linker change: both LTO variants pass `/PDBALTPATH:%_PDB%` to the DLL linker separately from the static archiver. Microsoft confirms that `%_PDB%` removes directory information from the embedded PDB reference; actual rebuilt-binary inspection remains outstanding. [Linker reference](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path)
