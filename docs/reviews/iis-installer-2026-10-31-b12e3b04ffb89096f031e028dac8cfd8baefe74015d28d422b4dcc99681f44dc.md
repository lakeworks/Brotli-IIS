## Analysis & Evidence

### 1. `install-iis.ps1` Compatibility, Quoting, and Exit Handling
- **PowerShell 5.1 & PowerShell 7+ Compatibility**:
  - The script adheres to syntax compatible with Windows PowerShell 5.1 and modern PowerShell 7+. It avoids PS 7-only language constructs (such as the ternary operator `?:`, null-coalescing `??`, or multi-argument `Join-Path`).
  - Native file hashing avoids `Get-FileHash`'s known Windows PowerShell 5.1 issue where `-WhatIf` suppresses hash calculation during dry-runs. The custom `Get-Sha256` function ([install-iis.ps1#L86-L93](../../install-iis.ps1#L86-L93)) uses .NET `System.Security.Cryptography.SHA256` directly and properly disposes streams.
  - AVX2 feature detection ([install-iis.ps1#L219-L226](../../install-iis.ps1#L219-L226)) calls Win32 `IsProcessorFeaturePresent(40)` (`PF_AVX2_INSTRUCTIONS_AVAILABLE`) via `Add-Type`, guarded by `if (-not ('BrotliIis.Cpu' -as [type]))` so repeated invocations in the same session do not fail due to type re-declaration.
- **Native Invocation & Argument Quoting to `appcmd.exe`**:
  - All native `appcmd.exe` invocations route through `Invoke-AppCmd` ([install-iis.ps1#L75-L82](../../install-iis.ps1#L75-L82)), capturing stderr and stdout (`2>&1`) and inspecting `$LASTEXITCODE -ne 0` to throw terminating exceptions under `$ErrorActionPreference = 'Stop'`.
  - When passing arguments containing whitespace (e.g., `%ProgramFiles%\IIS\IIS Compression\brotli-1.2.1.dll`), PowerShell array argument splatting (`& $AppCmd @Arguments`) passes the tokens cleanly to `CreateProcess`.
  - In collection additions (`/+[@start,...]`) and in-place attribute updates (`/[name='br'].<attr>:<val>`), string values are validated against containing single quotes ([install-iis.ps1#L129-L131](../../install-iis.ps1#L129-L131)) to prevent argument injection or malformed appcmd commands.
- **`-WhatIf` / `ShouldProcess` Coverage**:
  - `[CmdletBinding(SupportsShouldProcess = $true)]` is declared ([install-iis.ps1#L42](../../install-iis.ps1#L42)).
  - All modifying operations (backup creation, directory creation, undo note generation, DLL file copy, IIS config commits) are enclosed in an outer `$PSCmdlet.ShouldProcess($Section, ...)` block ([install-iis.ps1#L284-L311](../../install-iis.ps1#L284-L311)). Nested cmdlets use `-Confirm:$false` to avoid nested interactive confirmation prompts while respecting the outer transaction.
  - Service restart is separately guarded by `$PSCmdlet.ShouldProcess('W3SVC', ...)` inside `Restart-Www` ([install-iis.ps1#L182-L190](../../install-iis.ps1#L182-L190)).
  - When running under `-WhatIf`, `$WhatIfPreference` ensures the restart prompt is previewed without executing changes.
- **Idempotence**:
  - Target DLL presence and hash equality are checked at [install-iis.ps1#L247-L253](../../install-iis.ps1#L247-L253).
  - Scheme attributes and positional priority (`$br.First`) are evaluated at [install-iis.ps1#L263-L264](../../install-iis.ps1#L263-L264).
  - If the target DLL exists with matching hash, `br` is first with matching levels and attributes, and proxy settings match, the script outputs `Already installed with these settings; nothing to change.` ([install-iis.ps1#L271](../../install-iis.ps1#L271)) and makes zero changes.
- **Undo Note & Reversibility**:
  - `Get-UndoText` ([install-iis.ps1#L148-L179](../../install-iis.ps1#L148-L179)) generates standalone PowerShell commands that restore the previous scheme's DLL path and compression levels (or remove `br` if it was not previously registered), restore previous proxy settings, and offer the exact `appcmd restore backup` command for full metabase rollback. The note is written to disk *before* any configuration change is applied.
- **Partial Failure & Blast Radius**:
  - Scheme manipulation operates only on `[name='br']` in `system.webServer/httpCompression`. Sibling compression schemes (`gzip`, `deflate`), `<staticTypes>`, `<dynamicTypes>`, and site-level configurations are untouched.
  - Versioned DLL filenames (`brotli-<major>.<minor>.<patch>.dll`) prevent collisions with DLLs currently locked by `w3wp.exe`. Overwriting existing files with differing hashes is rejected ([install-iis.ps1#L249-L251](../../install-iis.ps1#L249-L251)).
- **`-VerifyUrl` Verification**:
  - Preflight validates that `-VerifyUrl` cannot be passed without `-RestartWww` ([install-iis.ps1#L204](../../install-iis.ps1#L204)), ensuring verification only runs against active workers running the newly loaded DLL.
  - `Test-BrResponse` ([install-iis.ps1#L192-L201](../../install-iis.ps1#L192-L201)) queries `curl.exe` with `-H "Accept-Encoding: br"`, verifies exit code, inspects `Content-Encoding`, and fails closed if the response is not encoded with `br`.

### 2. Triplet Linker Flags in `build-x64.ps1`
- `/PDBALTPATH:%_PDB%` is concatenated into `$dllLinkerFlags` alongside `$ltoLinkerFlag` ([build-x64.ps1#L101](../../build-x64.ps1#L101)).
- In the generated overlay triplet:
  - `VCPKG_LINKER_FLAGS_RELEASE` receives `$dllLinkerFlags` ([build-x64.ps1#L127](../../build-x64.ps1#L127)), applying `/PDBALTPATH:%_PDB%` to the shared library linker for `brotli.dll`. MSVC `link.exe` expands `%_PDB%` to the base filename (`brotli.pdb`), stripping all build-host directory paths from the debug directory RSDS entry.
  - `VCPKG_STATIC_LINKER_FLAGS_RELEASE` receives only `$ltoLinkerFlag` ([build-x64.ps1#L128](../../build-x64.ps1#L128)). The static-library archiver (`lib.exe`) is not passed `/PDBALTPATH`, avoiding `LNK4044` warnings or archiver failures.
