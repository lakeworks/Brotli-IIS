### 1. `install-iis.ps1` Execution & Behavioral Analysis

#### PowerShell 5.1 & PowerShell 7 Compatibility
The script adheres strictly to native Windows PowerShell 5.1 and modern PowerShell 7:
- Relies exclusively on core built-in cmdlets (`Get-FileHash`, `Test-Path`, `Copy-Item`, `Set-Content`, `Restart-Service`, `Add-Type`) and native utilities (`appcmd.exe`, `curl.exe`).
- Requires no external PowerShell modules (such as `WebAdministration` or `IISAdministration`), ensuring out-of-the-box execution on clean Windows Server images.
- Enforces strict mode (`Set-StrictMode -Version 2.0`) and terminating errors (`$ErrorActionPreference = 'Stop'`) without tripping on uninitialized automatic variables.

#### Native Argument Quoting & `appcmd.exe` Interactions
- **Invocation & Error Handling**: [`Invoke-AppCmd`](../../install-iis.ps1#L73-L80) passes `@Arguments` via splatting, captures combined stdout/stderr (`2>&1`), and validates `$LASTEXITCODE -ne 0`, raising terminating exceptions containing exact command arguments and exit text.
- **Collection Manipulation**: In [`Set-BrSchemeFirst`](../../install-iis.ps1#L115-L129):
  - When `br` is not yet first, removing (`/-[name='br']`) and re-adding at index 0 (`/+[@start,$list]`) uses comma-separated, single-quoted attribute values (`name='br',dll='...',...`). PowerShell wraps the entire argument in double quotes when constructing `lpCommandLine` because `$target` contains spaces (`Program Files`, `IIS Compression`). On arrival at `appcmd.exe`, single-quoted attributes are parsed properly by IIS collection syntax.
  - When updating an existing scheme that is already first, [`Set-BrSchemeFirst`](../../install-iis.ps1#L119-L122) applies `/[name='br'].<attribute>:<value>` updates in a single commit without modifying collection index or other schemes.
  - Single-quote injection is rejected up-front ([line 117](../../install-iis.ps1#L117)).

#### `-WhatIf` / `SupportsShouldProcess` Coverage
- The entire application sequence ([lines 257–284](../../install-iis.ps1#L257-L284)) is enclosed in a single `$PSCmdlet.ShouldProcess($Section, ...)` block summarizing the complete plan. Internal cmdlets suppress nested prompts via `-Confirm:$false`.
- Service restart in [`Restart-Www`](../../install-iis.ps1#L158-L166) is individually wrapped in `$PSCmdlet.ShouldProcess('W3SVC', ...)`.
- Under `-WhatIf`, zero mutations occur: no backup is added, no target directory or undo file is created, no files are copied, no IIS configuration is modified, and no service is restarted. If `-VerifyUrl` was supplied alongside `-WhatIf`, URL verification is safely skipped with an explicit log message ([line 292](../../install-iis.ps1#L292)).

#### Idempotence on Re-run
- [`install-iis.ps1`](../../install-iis.ps1#L219-L244) inspects the target file hash and existing configuration state. If the target DLL exists with matching SHA-256, `br` is first with identical attributes, and proxy settings match the requested flags, `$copyNeeded`, `$schemeNeeded`, and `$proxyNeeded` evaluate to `$false`.
- Re-running with matching parameters outputs `"Already installed with these settings; nothing to change."` and performs no disk writes, configuration changes, or redundant backups.

#### Preflight & Fail-Closed Guards
- **Elevation**: Enforced via `#Requires -RunAsAdministrator` ([line 1](../../install-iis.ps1#L1)).
- **Architecture**: Enforces `[Environment]::Is64BitOperatingSystem`. In addition, running in a 32-bit PowerShell session under WOW64 redirection fails closed immediately at [line 183](../../install-iis.ps1#L183) because `SysWOW64\inetsrv\appcmd.exe` does not exist on 64-bit IIS.
- **IIS Modules**: Queries `system.webServer/globalModules` via XML and verifies registration of both `StaticCompressionModule` and `DynamicCompressionModule`.
- **CPU AVX2 Validation**: Guarded via `kernel32!IsProcessorFeaturePresent(40)` (`PF_AVX2_INSTRUCTIONS_AVAILABLE`), preventing illegal instruction crashes in `w3wp.exe` if deployed on older virtualization profiles or hypervisors lacking AVX2 passthrough. Type definition re-registration in the same session is guarded via `(-not ('BrotliIis.Cpu' -as [type]))`.
- **Binary Hash & Versioning**: SHA-256 is validated against `-ExpectedSha256` before any action. `FileVersion` is validated against `^(\d+)\.(\d+)\.(\d+)` to produce a versioned filename (`brotli-<major.minor.patch>.dll`).
- **Target Collision Handling**: If `$target` already exists on disk with a divergent SHA-256, [lines 222–224](../../install-iis.ps1#L222-L224) throw an explicit refusal, preventing overwriting or corrupting a binary actively locked by worker processes.

#### Undo Note, Rollback & Partial Failure States
- Prior-round rollback tracking complexities (noted historically in rollback redesign closure notes) are cleanly resolved:
  - An IIS configuration backup (`appcmd add backup brotli-iis-<timestamp>`) is created prior to any file or configuration modifications.
  - The undo note (`brotli-iis-undo-<timestamp>.txt`) is written to `$TargetDir` before any configuration changes occur.
  - The undo note provides the exact invocation of `install-iis.ps1` targeting the previous DLL path and hash, the manual command to restore proxy attributes, and the exact `appcmd restore backup` command for total rollback.
  - If a step fails mid-execution (e.g. during `Set-BrSchemeFirst`), execution halts before reaching service activation. Worker processes retain their in-memory loaded module, leaving the operator with a clean backup and explicit undo instructions.

#### Verification Check (`-VerifyUrl`)
- `-VerifyUrl` enforces `-RestartWww` during preflight ([line 180](../../install-iis.ps1#L180)), guaranteeing the test never evaluates an un-restarted worker running stale DLL state.
- Executes `curl.exe -sS -o NUL -D - --max-time 30 -H "Accept-Encoding: br"`, correctly using a GET request rather than a HEAD request (which IIS static compression does not compress on first hit for uncached files), verifies curl return code, and asserts `Content-Encoding: br`.

### 2. Configuration Safety & System Isolation

- **Scheme Isolation**: Modifies only `scheme[@name='br']`. The preceding placement (`@start`) reorders `br` ahead of `gzip` and `deflate` without altering attributes on existing schemes.
- **MIME & Site Isolation**: `<staticTypes>`, `<dynamicTypes>`, and site-level `<location>` settings are untouched. All modifications are scoped to server-level `system.webServer/httpCompression` committed to `apphost`.

### 3. Linker Flag Delivery in `build-x64.ps1`

- In [`build-x64.ps1`](../../build-x64.ps1#L101-L128), `/PDBALTPATH:%_PDB%` is combined into `$dllLinkerFlags` and emitted to `VCPKG_LINKER_FLAGS_RELEASE` inside the overlay triplet.
- When vcpkg compiles `brotli-iis` as a shared library (`brotli.dll`), `VCPKG_LINKER_FLAGS_RELEASE` populates `CMAKE_SHARED_LINKER_FLAGS_RELEASE`. MSVC `link.exe` evaluates `%_PDB%` internally to write only the bare filename `brotli.pdb` into the CodeView debug directory entry, eliminating the build host's local paths.
- `VCPKG_STATIC_LINKER_FLAGS_RELEASE` receives only `$ltoLinkerFlag`, ensuring `lib.exe` (the static archiver) is never passed `/PDBALTPATH`.
- Both `-Lto on` and `-Lto off` triplets receive the flag correctly without impacting post-build axis verification.
