## Review

Three operational findings.

### [O1] Rollback can lose another compression scheme and then report success

At [install-iis.ps1:280](../../install-iis.ps1#L280), restoring a middle position removes and re-adds schemes following `br` in separate commits.

For an original order `deflate, br, gzip`, interruption between removing and re-adding `gzip` leaves it absent. Retrying rollback skips the missing scheme at line 281. The order check at line 289 excludes missing schemes from its expectations, so it passes and deletes the state file. Gzip remains unregistered server-wide.

Restore `br` without deleting unrelated schemes, or retain recoverable attributes for every removal and reject missing expected schemes. [Microsoft AppCmd collection operations](https://learn.microsoft.com/en-us/iis/get-started/getting-started-with-iis/getting-started-with-appcmdexe#editing-configuration-collections).

### [O2] An interrupted install can bypass the pending-restart check

The initial state written at [install-iis.ps1:393](../../install-iis.ps1#L393) contains `Completed=false`, but activation metadata is added only at [line 411](../../install-iis.ps1#L411).

If execution stops after the scheme update but before that final write, identical inputs subsequently take the no-change branch. [Test-PendingActivation](../../install-iis.ps1#L199) treats the missing activation flag as inactive, permitting `-VerifyUrl` to succeed against the previously loaded DLL.

Record pending activation before configuration changes and handle unfinished state even when configuration already matches. Microsoft requires a WWW restart for scheme DLL and level changes. [Scheme reference](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/httpcompression/scheme/#attributes).

### [O3] Rollback discards activation and retry state before restarting

At [install-iis.ps1:300](../../install-iis.ps1#L300), rollback removes the state file before `Complete-Activation`.

Without `-RestartWww`, pending activation therefore disappears after the invocation. A later no-change install matching the restored configuration can verify the still-loaded newer DLL. If the requested restart fails, repeating the documented rollback command instead stops at “No install state found,” before attempting activation.

Retain a rollback-completed/pending-activation state until activation succeeds or a later reboot establishes it. The same [Microsoft restart requirement](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/httpcompression/scheme/#attributes) applies to restoring the previous scheme.

Static inspection supports the linker change: both LTO variants forward `/PDBALTPATH:%_PDB%` to DLL linking separately from the static archiver. Microsoft documents `%_PDB%` as the filename without directory information. Actual rebuilt-binary inspection remains outstanding. [Linker reference](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path).

The inspected local IIS schema supports the compression-level correction. No added identifying literals were found in the examined diff and commit subjects. No tests, builds, installer execution, delegation, or modifications were performed.
