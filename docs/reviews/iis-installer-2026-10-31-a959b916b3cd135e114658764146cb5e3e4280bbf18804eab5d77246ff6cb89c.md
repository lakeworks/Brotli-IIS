### [O1] Soft-restore commands fail after a mid-move partial failure

`Set-BrSchemeFirst` documents a two-commit window when `br` exists and is not first (`install-iis.ps1:113-116`, `:126-130`): remove `br`, then re-add at `@start`. If the remove commits and the re-add throws, `applicationHost.config` has no `br` scheme.

The undo note written just before that call (`:267-269`) still emits soft-restore as attribute sets on an existing `br` (`:149-150`):

```text
/[name='br'].dll:… /[name='br'].dynamicCompressionLevel:… …
```

Those commands require `br` to be present, so they fail in this state. Full `appcmd restore backup` at `:160` still works, and the backup name was printed at `:269`, but the note lists soft-restore first with no warning that a missing `br` means skip to full revert (unlike the missing-DLL warning at `:152`). An operator following the printed soft path after an interrupted move gets an `appcmd` error and may not reach the working restore line.

Workers keep the previously loaded DLL until a WWW restart, and other schemes stay untouched; the gap is recovery messaging and soft-undo usefulness in the window the script itself creates.

### [P1] Readme hand-check uses HEAD; the script verifier uses GET

`readme.md:19` tells operators to verify with `curl.exe -sI` (HEAD). `Test-BrResponse` (`install-iis.ps1:176`) uses a GET (`-sS -o NUL -D -`) and never passes `-I`. Align the hand-check with the script’s request shape so a manual follow-up cannot disagree with `-VerifyUrl` on the same URL for reasons unrelated to the install.
