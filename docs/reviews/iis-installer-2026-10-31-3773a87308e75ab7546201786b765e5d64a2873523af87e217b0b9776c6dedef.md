## Review

### [O1] Record pending activation before rollback changes configuration

`install-iis.ps1:286–302` restores `br` and proxy attributes before writing `ActivationPending=true`. If restoration partly succeeds and a later command or the order check fails, the previous state can still say activation is complete.

Concrete case: install and restart successfully, add another compression scheme, then roll back. Restoration changes `br`, but the full-order comparison fails because of the added scheme. The restart is never reached, and the state still reports no pending activation. Subsequent verification can therefore accept the currently loaded DLL despite the restored configuration requiring a restart. [Microsoft documents that restart requirement](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/httpcompression/scheme/#attributes).

Persist pending activation before the first rollback mutation, retaining the original recovery data until restoration and activation succeed.

### [O2] Rejecting a middle-position `br` drops an agreed installation case

`install-iis.ps1:349–352` refuses configurations such as `gzip, br, deflate`. The agreed plan explicitly requires moving an existing non-first `br` to the start (`docs/reviews/iis-installer-arc-2026-10-31.md:24`).

This leaves the operator doing manual IIS edits for a required deployment scenario. The refusal is documented in help, but is absent from the recorded plan deviations. Implement this case with recoverable ordering, or resolve the scope change explicitly before claiming plan completion.

### [P1] Recovery metadata bypasses `-Confirm`

`install-iis.ps1:374–376` writes `Completed=true` outside any `ShouldProcess` block and explicitly suppresses confirmation.

After an interrupted installation whose configuration already matches, rerunning with `-Confirm` silently modifies the state file despite the help promising confirmation for the change set. Under `-WhatIf`, the write is suppressed but its intended change is not printed. Put this recovery write behind `ShouldProcess`. [PowerShell confirmation guidance](https://learn.microsoft.com/en-us/powershell/scripting/learn/deep-dives/everything-about-shouldprocess#pscmdletshouldprocess)

Static inspection supports the linker change: both LTO variants forward `/PDBALTPATH:%_PDB%` to DLL linking separately from the static archiver. Microsoft defines `%_PDB%` as the PDB filename without directory information. Rebuilt-DLL inspection remains a release check. [Linker reference](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path)

Coverage: inspected the candidate diff, installer paths, pinned vcpkg toolchain and local compression schema. No new host-specific identifiers found in the inspected additions. No tests, builds, installer execution or service changes were performed; PowerShell/IIS runtime behavior remains unverified.
