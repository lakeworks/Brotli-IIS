## Review

### [O1] Declining installation can still verify the previous DLL

At `install-iis.ps1:264`, declining the configuration change skips installation, but execution still reaches the restart and verification at `:295–298`.

With an existing Brotli installation, run an upgrade with `-Confirm -RestartWww -VerifyUrl`, decline installation, then accept the restart: the old DLL can answer `br`, producing “Verified” without installing the candidate. This contradicts the help’s assurance at `:34`. Gate activation and verification on either successful application or configuration already matching the requested state. [PowerShell confirmation behavior](https://learn.microsoft.com/en-us/powershell/scripting/learn/deep-dives/everything-about-shouldprocess)

### [O2] Proxy-only activation prints an unusable command

When only proxy attributes change, `install-iis.ps1:311` prints:

`appcmd list apppool /xml | appcmd recycle apppool /in`

AppCmd is absent from PATH by default, so these instructions fail on the documented fresh-server setup. Print PowerShell invocations using the resolved `$AppCmd` path on both sides of the pipe. [Microsoft AppCmd reference](https://learn.microsoft.com/en-us/iis/get-started/getting-started-with-iis/getting-started-with-appcmdexe#how-to-use-appcmdexe)

Static tracing supports `/PDBALTPATH:%_PDB%` reaching DLL linking in both LTO variants without reaching the static archiver. Microsoft confirms `%_PDB%` excludes directory information; rebuilt-binary inspection remains a release check. [Linker reference](https://learn.microsoft.com/en-us/cpp/build/reference/pdbaltpath-use-alternate-pdb-path)
